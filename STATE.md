# Состояние проекта

## Разработка

В соответствии с [ТЗ](TZ.md) и [контрактом](CONTRACT.md) реализован статический сайт: `index.html`, `styles.css`, `app.js`, `storage.js`. Текст задач выводится через `textContent`; операции выполняются по ID. Новые функции и редизайн на этапе упаковки не добавлялись.

## Проверки

- Проверен синтаксис JavaScript с помощью `node --check`.
- Отдельный повторный этап тестирования: 11 проверок PASS в Playwright 1.65.0 / headless Chromium 158.0.8127.18. Подробности: [исходник тестов](tests/browser.cjs), [очищенный лог](tests/results.log), [скриншоты](tests/screenshots/).
- В браузерных тестах проверены добавление, пустой ввод, дубликаты и действия по ID, восстановление, безопасный вывод HTML-подобного текста, вёрстка 375 px, клавиатура и видимый фокус, ошибки и повреждение хранилища. Переполнение проверено фактическим исчерпанием квоты браузера, недоступность — имитацией SecurityError.
- Тест чувствительности: в отдельной временной копии отключена проверка пустого ввода; тест ожидаемо упал, код 1. [Очищенный лог](tests/mutation.log). Git checkout не использовался.
- Визуально просмотрены четыре скриншота: пустой и заполненный список при 375×812 и 1440×900. Обрезанную на мобильном экране подсказку сократили; после исправления весь прогон повторили.
- Локальное открытие `index.html` через `file://` и сохранение после обновления проверены в headless Chromium 158.0.8127.18.
- Установка Playwright 1.65.0 и Chromium в чистой временной копии и запуск тестов без ссылки на прежний npm-кэш проверены: 11 PASS. Инструкции в [README](README.md).

## Не проверено и ограничения

Другие браузеры, реальные мобильные устройства, скринридеры, полная доступность и одновременное редактирование в нескольких вкладках не проверены. Данные привязаны к браузеру и адресу, без синхронизации и резервной копии; `file://` может вести себя иначе в разных браузерах. Ошибка записи оставляет изменения только в памяти. Повреждённые данные автоматически не перезаписываются, встроенного восстановления нет.
